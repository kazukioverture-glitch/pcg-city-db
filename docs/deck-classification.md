# 実データ分類 v1

## 設計とセルフチェック

既存の `deck_classifications` sidecar とatomic writeだけを使います。
collector、収集workflow、元3 JSON、schemaは変更しません。
収集の成功条件に分類器を追加せず、週次分析前に明示期間を指定して実行します。
範囲外の既存分類は保持し、別分類器・手動分類と競合したら保存前に停止します。
同じ入力の再実行は分類日時も含めて変更しません。欠損デッキはバッチ全体を中止します。
60枚不整合は `unknown` とし、親・派生を割り当てません。

カードを部分一致で数えません。`analysis/classification_cards.json` は今回DBに存在する
12名称の収録IDと完全一致の表示名を列挙した小さな分類専用辞書です。
枚数は同名の別収録も合算します。ノココッチexはノココッチに含めません。
新しいID・表示名は自動推定せず、辞書と分類器版を明示更新してください。
根拠には一致枚数、判定理由、元デッキ全体のSHA256を保存します。
これは公式カードマスターや全デッキを網羅した分類器ではありません。

| 親分類 | 必要枚数 |
| --- | --- |
| ドラパルトex | 2枚以上 |
| メガガルーラex | 3枚以上（既決定の閾値） |
| オーガポン みどりのめんex | 3枚以上 |

メガガルーラとオーガポンが両立した場合はメガガルーラを優先します。
ドラパルトと別の親が両立した場合の優先順位は未決定なので `unknown` です。
3親に該当しないものも `unknown` で残します。「その他のデッキ」と断定しません。

ドラパルトは非exのノココッチ・ヨノワール各1枚以上を構築タグとして記録し、
両方あれば両方を保存します。これらは主アタッカーのラベルではありません。

| 親 | 対応する主アタッカー候補 |
| --- | --- |
| メガガルーラex | メガレックウザex、ヤドキング、タケルライコex、ヒビキのホウオウex |
| オーガポン みどりのめんex | カミツオロチex、オリーヴァex、メガフシギバナex、タケルライコex |

派生の自動判定は「対応候補が一意かつ合計2枚以上」を保守的な構造ルールとします。
枚数の最大値だけで主アタッカーを選びません。候補が複数、1枚のみ、候補なしでは
親だけを保存し `partial` とします。未対応アタッカーの網羅性や実際の攻撃頻度は検証不能です。
自動判定はリスト構造による分類であり、対戦での主攻撃役を観測した事実とは区別します。
メガレックウザexと共存するヒビキのホウオウexはエネルギー補助側として候補から外します。
ファイアローex、ラティアスex、ニャースex等の補助採用を派生名には使いません。

## 投入と再利用

```sh
python -m analysis classify-decks --start 2026-09-23 --end 2026-09-29
python -m analysis classify-decks --start 2026-09-30 --end 2026-10-06
python -m analysis validate-state
```

全カテゴリの公開結果に紐づくコードを対象とし、親分類にはカテゴリを混ぜません。
分析時は大会の日付・カテゴリ・順位で母集団を選び、deck_codeで分類をjoinします。
分類レコード件数は公開枠数やTop8占有率の分母ではありません。

既存W02 FINALの入力コピーは分類投入前の空ファイルを含み、そのまま保護します。
分類後の分析をそのFINAL由来と偽って報告しないでください。
再現用に分類済みsidecarと分類器・辞書も含む新しいsnapshotを別IDで保存してください。
既存FINALを差し替えません。CLIも `weekly_snapshots` 内への分類出力を拒否します。
過去コピーを分類したい場合は `--city` / `--decks` で読取り元を指定し、
`--output` をsnapshot外の新しいsidecarに指定できます。
