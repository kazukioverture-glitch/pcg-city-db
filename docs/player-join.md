# D: プレイヤー実績JOIN v1

## 設計・セルフチェック

- 取得範囲：既存の公開Top8結果のIDだけ。全参加者ID取得、プロフィール巡回、外部通信は追加しない。
- 実行時期：週次分析時だけ。30分収集・Termux・Actionsの変更なし。
- 保存：選手マスタ、履歴コピー、JOINキャッシュは作らない。JSONを標準出力し、分析で必要な場合だけ入力ハッシュと共に保存する。
- 照合：文字列player_id完全一致。先頭ゼロ保持。名前で名寄せしない。カテゴリ不明はJOIN不能。
- 時点：対象大会より前の日だけ。同日大会は開催順が不明なので除外。履歴下限を必須指定する。
- 重複：大会ID、同一大会内の選手ID、分類コードの重複は失敗。集計してから不正データを保存しない。
- 既存DB・FINAL・分類には一切書き込まない。依存ライブラリ追加なし。

## 実行

```bash
python -m analysis join-players --start 2026-09-30 --end 2026-10-06 --history-start 2026-09-23
```

`--city`と`--classifications`で固定した入力を選べる。FINALを分析するときは保存済み入力を指定し、最新DBを代用しない。分類は入力に対応したものを使う。出力のinput_sha256は読み込んだJSON値の正規化ハッシュでありGit commitやファイルバイトのハッシュではない。

## 指標の意味

| 項目 | 意味 |
|---|---|
| observed_prior_top8 | 履歴下限以降・同カテゴリ・大会前日までの公開Top8観測件数 |
| observed_previous_season_top8 / best_rank | 明示した昨季期間内の観測件数と最良順位 |
| observed_same_parent_prior_top8 | 同じ親アーキタイプで過去Top8に入った観測件数 |
| csp_evidence | 出典・対象季・確認日付きのCSP観測。大会前日までに確認されたものだけ |

昨季を計算する場合は`--previous-start`と`--previous-end`を両方指定する。昨季データがcity入力に含まれていることが必要。自動取得や季節境界の推測はしない。0件は「入力内で観測0件」であり「入賞経験なし」ではない。未指定の昨季、欠損ID・カテゴリ、分類不能、未取得CSPはnull。

同じ親アーキタイプの再使用は、同一60枚リストや連続使用の証明ではない。全出場結果がないので連続使用は判断不能。ドラパルトの派生違いも同じ親に含む。大会結果のpointsをCSPとして合算しない。

## CSP補助入力（任意）

`--facts facts.json --csp-season 2027`でJSON配列を指定する。項目は下記7項目に限定し、氏名・住所・プロフィール本文は不要。分析対象外のIDはJOIN対象外。

```json
[{"player_id":"0000000001","category":"オープン","season":"2027","as_of":"2026-09-28","verified_on":"2026-09-29","csp":100,"source_url":"https://example.org/evidence"}]
```

上記は形式例で、実績データではない。source_urlは確認した公開情報の出典を指定する。as_ofは数値の対象日、verified_onは実際の確認日。対象季とカテゴリが一致する情報だけを採用する。同じ最新対象日の複数観測は曖昧なためnull、同一キーの重複はエラー。出典の真偽の確認は情報収集工程が担い、URL文字列だけを根拠に自動認証しない。
